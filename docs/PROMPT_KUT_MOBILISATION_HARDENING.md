## 1. What exists, so you do not rebuild it

The KUT mobilisation pack is four issued documents plus their generators. Mobilisation began
the week of 25 August 2026; the pack is being relied on now.

| Artefact | Generated by |
|---|---|
| `KUT_BIM_Execution_Plan.docx` | `tools/build_bep.py` |
| `KUT_Project_Delivery_Playbook.docx` | `tools/build_team_playbook.py` |
| `KUT_Master_Information_Delivery_Plan.xlsx` | `tools/build_midp.py` |
| `KUT_BIM_MANAGER_PLAYBOOK_INTERNAL_STINGTOOLS.docx` | hand-maintained, **private** |
| `project-templates/KUT/_BIM_COORD/lod_matrix.json` | `tools/build_kut_lod_overlay.py` |
| Shared house style | `tools/corporate_docx.py` |

**Two rules that govern everything below.**

1. **The three issued documents never name the tooling.** No product name, no command name,
   no parameter name, no file path, no `.json`. They are read by the client and by every
   consultant. Express a requirement as an outcome or an obligation. This is both an
   intellectual-property boundary and better BEP writing: the Appointing Party is entitled to
   require a check, not to specify the instrument.
2. **Never hand-edit a generated file.** Edit the generator and regenerate. Two hand-copies of
   one document is the failure this whole workstream exists to remove.

## 2. The gaps, in priority order

### G1 — The issued documents have no gate (highest value)

**The defect.** `tools/check_smoke_test.py` proves the smoke-test checklist against the code it
describes. The three issued documents have no equivalent. Their cross-document consistency was
verified once, by an ad-hoc script that was never committed: 14 checks covering stage LODs,
stage names, suitability codes, role codes, cadence, the originator open item and the tier
language. Those checks will rot the moment someone edits one generator and not the others.

**Recommended fix.** `tools/check_kut_documents.py`, stdlib-only, CI-gradable, modelled on
`check_smoke_test.py` — read that file first; it is the pattern this repo already trusts.

Assert at least:

1. **Regeneration is a no-op.** Each generated document rebuilds byte-identically, or the
   check fails naming which one is stale. The `.docx` files are already deterministic (fixed
   epoch in core properties, fixed zip entry timestamps). Confirm the `.xlsx` is too — openpyxl
   may stamp a creation time, and if it does, pin it before asserting freshness.
2. **Cross-document agreement.** Stage names, months and LOD values identical across BEP,
   playbook and MIDP. Suitability codes. Role codes. The volume table. The document references
   (`KUT-PLN-ZZ-ZZ-RP-Z-0001` and `-0002`) resolve to the documents that claim them.
3. **The asset tiers agree with the data.** The tier tables in the BEP and playbook must match
   `project-templates/KUT/_BIM_COORD/lod_matrix.json`. This is the check that matters most:
   the documents tell a contractor what to capture, and the gate decides whether they passed.
   If those two disagree, somebody is failed for a field nobody asked them for. Derive the
   expected table from the JSON rather than hard-coding it.
4. **No tooling leakage.** Fail on any product name, command tag, parameter name (`ASS_`,
   `COM_`, `MNT_`, `FLS_`, `PRJ_`), file path or `.json`/`.py` extension appearing in the three
   issued documents. The internal `.docx` is exempt — exclude it explicitly by name.
5. **Placeholders are counted, not forbidden.** `[FILL]` is legitimate at Rev P01. Report the
   count per document and fail only if it *rises* against a committed baseline file, so the
   pack converges toward issue instead of quietly acquiring new holes.

Wire it into a workflow modelled on `.github/workflows/smoke-test-gate.yml`, and add
`python tools/build_kut_lod_overlay.py --check` to the same job — it exists and is CI-ready but
nothing runs it.

**Prove it works by breaking it.** Change a stage LOD in one generator only; change a tier in
the JSON without the documents; leave a document stale; insert a parameter name into the BEP.
Four distinct, actionable failures, then revert. A gate you have only seen pass is not a gate.

### G2 — Date format is mandated and unenforced

**The defect.** Every date parameter in the registry is `TEXT`. The BEP mandates `YYYY-MM-DD`.
Nothing checks it. Three conventions will coexist and it surfaces at M44, when the handover
dataset is assembled and the dates cannot be sorted or compared.

**Recommended fix.** A validator over the date-typed asset parameters, reporting non-conforming
values by category and volume, run as part of the monthly asset-data completeness report rather
than only at the gate. Find where the completeness report is produced and add it there. If the
report does not exist as code yet, say so and log it — do not invent a new command surface.

Consider also: `ParameterHelpers` is where a `SetDate`/`GetDate` pair would belong if you judge
the fix should be at the write side instead. Do not do both.

### G3 — Deprecated parameters remain selectable

**The defect.** `ASS_INST_DATE_TXT` and `COM_INSTALL_DATE_TXT` are marked DEPRECATED in
`PARAMETER_REGISTRY.json` but still appear wherever parameters are listed. Their GUIDs may be
bound in existing models, so they **cannot be deleted** — a prior session established this and
chose deprecation over removal deliberately. Do not reverse that.

**Recommended fix.** Honour the deprecation in the UI: filter parameters whose description
begins `DEPRECATED` out of picker lists, or sort them last under a clear heading. Find every
picker that enumerates the registry. Leave the data alone.

**Watch for**: `ASS_INSTALL_DATE_TXT` is a *C# constant* already redirected to the canonical
parameter — it is not itself a deprecated parameter and must keep working. Check before you
filter on name.

### G4 — Untested code paths behind the handover deliverable

**The defect.** Three fixes landed on this branch and none is exercised by a test:

- `ComplianceScan` read a hard-coded `"ASS_INSTALL_DATE_TXT"` that nothing writes, so the QA
  gate's install-date test always saw empty. Now reads `ParamRegistry.INSTALL_DATE`.
- COBie **export** read `COM_INSTALL_DATE_TXT` while COBie **import** writes
  `ASS_INSTALLATION_DATE_TXT`, so an imported COBie file did not survive a re-export. Export now
  reads canonical first with a legacy fallback.
- The LOD 500 tier requirements are new and have never run against a model.

**Recommended fix.** The COBie round-trip is the one worth a test: export → import → export
should be stable. Check whether it can be exercised without Revit — if the field mapping is
separable from the Revit calls, extract it the way `LodMatrixModel` was extracted for
`StingTools.Tags.Tests`, and test that. If it genuinely cannot be, say so, and add the
round-trip to the smoke-test source as a step with `reach: "button"` so a human runs it.

Do not write a test that needs Revit. It will not run.

### G5 — The MIDP round-trip is manual

**The defect.** Each appointed party completes the TIDP sheet and returns it; the Information
Manager merges the rows into the MIDP by hand. Nine consultants, re-baselined every stage, is
enough repetition to go wrong quietly — a dropped row is invisible.

**Recommended fix.** `tools/merge_tidp.py`: read one or more returned TIDP workbooks, validate
against the same permitted-value lists the workbook uses, and report what would be added,
changed or conflict — **preview by default, write only on `--apply`**. Match on the Ref column.
Refuse to merge a row whose Ref already exists with different content unless told to.

Reuse the `LISTS` and `COLS` definitions in `tools/build_midp.py` rather than restating them;
if that means extracting them into a small shared module, do it.

### G6 — Documents not registered in the repo index

`docs/INDEX.md` is the table of contents for the documentation set. The four KUT documents, the
five generators and the shared style module are not in it. Add them, with status. Small, but it
is how the next person finds this.
