# TaskDialog.Show / new TaskDialog were not counted; the entries below the "A8" marker are what
# widening the scan found. The first-line no-document guard is not counted (see the checker).
#
# THIS LIST ONLY SHRINKS. tools/check_unattended_cycle.py fails if a NEW construct appears,
# if a baselined count RISES, if it FALLS (so a fix has to lower the line in the same
# commit), and if a baselined entry stops matching anything at all -- a baseline that
# describes code that is gone claims health it has not checked.
#
# READ THE REASONS, NOT THE COUNT. Two kinds of entry live here and they are not the same:
#
#   GATED   -- the construct exists but AccOperatingPolicy decides whether it runs. In
#              unattended mode the branch is not taken, and the command either uses the
#              configured answer or fails with a named reason. These are done.
#
#   UNGATED -- the construct always runs. It is a REAL remaining blocker to unattended
#              operation and it is written down as one, not quietly counted. Do not read a
#              green run as "the cycle is unattended" while an UNGATED line is present.
#
# The checker cannot tell those two apart -- it reads source text, not control flow -- which
# is exactly why each line carries a reason a person had to type.
#
# Format:  <relative path>::<Class>|<construct>|<count><TAB>GATED|UNGATED - reason
